This file is for playing a session of the role-playing game /[[https://timhutchings.itch.io/tyov][Thousand Year Old Vampire]]/ by [[https://thousandyearoldvampire.com/][Tim Hutchings]]. It helps play the standard single player version of the game. This file keeps track of what prompt you are on; calculates which prompt to do next; and helps you keep a record of play. This record includes experiences; memories; diary entries; skills; resources; characters; marks; and forgotten/lost/checked/expired things.

The file assumes you are playing the standard version of the game, and own a copy of the original game. If you are using different prompts from the standard ones, you may need to alter the =#+ALL_PROMPTS= variable (though the supplied functions currently don't work for prompts with more than nine variants).

In response to prompts, you may need to occasionally change the variable: =#+CURRENT_PROMPT= in [[*Play Variables][Play Variables]].

In order to run code blocks without confirmation for this Emacs session (affects all buffers)---which makes this file far more pleasant to use---run the following code block at the start of your play session by placing your cursor at the end of the =setq= line after the closing parenthesis and hitting ~C-x C-e~.

* Instructions
In this game you will create a fictional vampire and chronicle their life over a very long period of time. The vampire will be represented by five Traits:

- /Memories/
- /Skills/
- /Resources/
- /Characters/
- /Marks/

The game is played by responding to Prompts, chosen randomly. Almost all Prompts will force you to modify the above Traits, as well as create an Experience. Experiences are created in one of your five Memories (which can store three Experiences each). You cannot edit an Experience after you have moved onto another Prompt. Experiences can never be moved or deleted individually. You can free up entire Memories by moving them to your Diary or forgetting them (in both cases, taking all the attached Experiences with them). Once in your Diary, Memories become Entries. You can have up to four Diary Entries at any one time, and you can keep moving Memories into your Diary until you hit this number. You cannot add Experiences to Diary Entries, or edit them. Even in Diary Entries, Experiences can never be moved or deleted individually. Although you cannot free up space in a Diary by forgetting individual Entries, you are free to discard the entire Diary (taking all the attached Entries and Experiences with it) and start a new one.

When you forget a Memory or lose/discard a Diary, you cannot refer to it anymore because it no longer exists in your mind and you have no way to reference it.

You may store up to five current Memories, made up of at most three Experiences each. Up to four Memories can individually be moved to your Diary (becoming Entries). If you have run out of Memories in which to store Experiences, you must move a Memory to be Forgotten from current Memories, or to your Diary (as an Entry). To change a Memory or Diary Entry to something else, hit ~C-c C-t~ while your cursor is on it, then select the desired option. Experiences within a Memory should connect logically together. If an Experience doesn't thematically fit inside any current Memory, a new Memory will need to be used (potentially requiring Memory management). Keep in mind that you can only forget/move entire Memories (not individual Experiences) and that Experiences cannot be moved between Memories once recorded.

Your Diary is a physical Resource and should be listed as one. Once a Memory has been moved to your Diary as an Entry, you can no longer add Experiences to it, and you will take whatever is written there as the absolute truth, with no additional knowledge about the events described. You also cannot forget individual Entries in your Diary. You can be told that you've lost your Diary, however, in which case all those Entries would then be marked as Forgotten at the same time. You can create a Diary whenever you need one, but you may only have one at a time and any previous Diaries will be lost.

If a Prompt tells you that you lose your Diary, all Entries in it must be Forgotten as well, requiring you to create a new Diary. You may only have one Diary at a time.

You can mark a Memory as forgotten, or move it to a Diary using ~C-c C-t~ when the cursor is on the Memory's heading.

An Experience should take the form of:

*- prompt number as X.X: Scene setting and event description; personal impact, such as how you feel or how you responded---additional information.*

For example:

~- 1.1: Stalking the deserts over lonely years, I watch generations of Christian knights waste themselves on the swords of the Saracen; it’s a certainty that Charles is among them---I dream of his touch as I sleep beneath the burning sand.~

Here, the prompt number ~1.1~ indicates that this is the first of the `one' Prompts. In the standard version of the game, all but end-game Prompts contain three variants. The number after the point indicates the variant, with ~.1~ being the first, ~.2~ being the second, and so on. This file will tell you which variant to use.

When a Prompt tells you to check a Skill, incorporate it into your new Experience, then check it off in the Skill List (using ~C-c C-c~). You may only check a Skill once unless told otherwise. You can still use a checked Skill to resolve Prompts; you just cannot check it again. If, however, a Prompt tells you to Lose a Skill, then it can no longer be used to resolve a Prompt. To indicate that a skill is lost, enclose its text with a ~+~ symbol on either side.

Resources are assets available to you. A Stationary Resource is one that cannot be taken with you as you travel. A Lost Resource cannot be used. You can have other `resources' available to you as would make sense to your current situation when resolving Prompts; they just cannot be used as part of the game mechanic of creating and losing Resources when instructed by a Prompt. To indicate that a Resource is lost, enclose its text with a ~+~ symbol on either side.

If you run out of Skills to check, you can lose a Resource instead. If you run out of Resources, you can check a Skill instead. Either occurrence should suggest the most dire of circumstances for your vampire. If you run out of both, then you cannot resolve the Prompt, and the game ends.

Characters are people whom your vampire has a relationship with. Extend their descriptions each time you interact with them. Characters, like Resources, can also be used to resolve Prompts when writing experiences. Characters can be Mortal or Immortal (you can tag them to help you remember using ~C-c C-q~). Mortal Characters can eventually Expire (die). You can set their existential state using ~C-c C-t~ when the cursor is on their heading.

Marks are visible indications that your vampire is not a Mortal person. You may sometimes try to conceal them in some way. Once created, a Mark exists for the rest of your vampire's existence.

You should only create Skills, Resources, Characters, and Marks when told to by a prompt (unless otherwise specified above).

Start the game by creating a short history for your soon-to-be vampire (generally sometime long ago). Store this as an Experience (numbered as 0.1) in a Memory. Then, create at least three Mortal Characters that your vampire had a relationship with when they were mortal (these Characters will likely not be around for long). Give your vampire-to-be three Skills fitting their current history, and three Resources they obtained while Mortal. Create three Experiences (none of which can exist in the same Memory as each other). Number these as 0.2, 0.3, and 0.4. Each of these Experiences should combine two of your soon-to-be vampire's Traits. Next, create an Immortal Character: the creature that turned you. Create a Mark that indicates how this was done, and record it as an Experience (0.5) that must initially be in its own Memory.

Once you have finished with your vampire, they will have three Skills, three Resources, a Mark, at least three Mortals, one Immortal, and one Experience in each of their five Memories.
** Playing The Game
Start the game by placing the cursor into the [[*Gameplay Functions][Gameplay Function]] called =get-next-prompt= and hitting ~C-c C-c~. It will create a results section underneath, displaying the Prompt from the book that needs resolved. Continue to do this each time you are ready to move onto the next Prompt. You can similarly use the other [[*Gameplay Functions][Gameplay Functions]] to do convenient things. These are:

- =reset-used-prompts=---have the game forget which Prompts you have visited thus far
- =reset-current-prompt=---have the game go back to the first Prompt in the book
- =reset-playspace=---delete everything you have created under the [[*Play Space][Play Space]] heading
- =restart-game=---have the game forget which Prompts you have visited thus far, and go back to the first Prompt in the book
- =reset-game=---have the game forget which Prompts you have visited thus far, go back to the first Prompt in the book, and delete everything you have created under the [[*Play Space][Play Space]] heading

You might be able to undo the above actions by immediately hitting ~C-/~ right after.
** Ending The Game
If you run out of Skills and Resources such that you cannot satisfy a Prompt, the game ends. Similarly, if you can't resolve a Prompt for any other reason, the game ends.

The other way for the game to end is if a Prompt tells you the game is over.

When the game ends, write one final Experience to conclude your chronicle.
** Journaling Gameplay Variant
The above describes the `quick' gameplay style of /Thousand Year Old Vampire/, but you can also play it as a `journaling' game. In this variant (while playing the game as normal), you also keep a more detailed Journal Entry for each Prompt (usually a paragraph or two for each one).

This is not related to your Diary, but is a separate document that does not interfere with any other rules. You cannot refer to your Journal to subvert the Memory mechanic of the game.

While you may need to edit or discard past Journal Entries to better fit in with the game as it progresses, you can never modify Experiences in the main game to accommodate your Journal.

You can then, hopefully, end up with a narrative document at the end of play, allowing you to read over the story of your vampire's life.

The code block, =prompt-number-generator=, was used to create the =#+ALL_PROMPTS= variable. By changing the variables in the code block declaration, it could be used to update =#+ALL_PROMPTS= to match a game with the same prompt structure as /Thousand Year Old Vampire/ (perhaps /[[https://www.drivethrurpg.com/en/product/453826/tales-from-the-gods][Tales from the Gods]]/ by Axo Stories).

#+name: prompt-number-generator
#+begin_src emacs-lisp :tangle no :var main-prompts=71 prompt-variants=3 end-game-prompts=9 :results silent
  ;; This generates a list that can be used as the value for ALL_PROMPTS. It assumes that end-game-prompts have no variations and come after the main Prompts.
  (let ((x 1)
        (y 1)
        (z 1)
        (prompt-list "("))
    (while (< x (1+ main-prompts))
      (while (< y (1+ prompt-variants))
        (setq prompt-list (concat prompt-list (format "%d.%d " x y)))
        (setq y (1+ y)))
      (setq y 1)
      (setq x (1+ x)))
    (while (< z (1+ end-game-prompts))
      (setq prompt-list (concat prompt-list (format "%d.1 " (+ main-prompts z))))
      (setq z (1+ z)))
    (setq prompt-list (concat (string-trim-right prompt-list " ") ")"))
    (when (derived-mode-p 'org-mode)
      (save-excursion
        (let ((regexp (format "^[ \t]*#\\+%s:" (regexp-quote "ALL_PROMPTS")))
              (case-fold-search t))
          (goto-char (point-min))
          (when (re-search-forward regexp nil t)
            (insert " ")
            (delete-region (point) (line-end-position))
            (insert (format "%s" prompt-list))))))
    (print prompt-list))
#+end_src

After cleaning (BOM stripped, CRLF converted to LF) the official text file (=_Thousand Year Old Vampire.txt=) for the game, we can now parse the string to return a hash table containing all the Prompts. I've added a lot of comments to the =parse-clean-txt= code block because there were a number of gotchas while making it.

#+name: parse-clean-txt
#+begin_src emacs-lisp :tangle no :var new-clean-txt="" :results silent
  (defun parse-clean-txt (clean-txt)
    (with-temp-buffer
      (insert clean-txt)
      (goto-char (point-min))
      (let* ((in-section nil)
             (found nil)
             (current nil)  ; The current Prompt being processed, stored as an assoc list: (KEY . LINES)
             (table (make-hash-table :test 'equal)))
        (while (not (eobp))  ; eobp is the end of buffer predicate, which is faster here than my usual check that point is less than point-max
          (let* ((line (string-trim (buffer-substring-no-properties (point) (line-end-position)))))  ; Don't get text properties (to improve performance)
            (cond
             ;; Prompts section not yet found.
             ((not in-section)
              ;; Only say we're in this section after the first encountered "Prompts" heading.
              (when (and (not found) (equal line "Prompts"))
                (setq in-section t
                      found t)))
             ;; When line matches at least three underscores, we've just left the main Prompts section. Tidy up final found Prompt before closing out section.
             ((string-match "^[_]\\{3,\\}$" line)
              (when current
                (puthash (car current) (mapconcat #'identity (cadr current) " ") table)
                (setq current nil))
              (setq in-section nil))
             ;; Either the Prompt number and variant, or Prompt number and variant followed immediately by the Prompt (5 groups total: 1--5).
             ((string-match "^\\([0-9]+\\)\\([abc]\\)$\\|^\\([0-9]+\\)\\([abc]\\)\\. \\(.*\\)$" line)
              ;; Add match from previous loop iteration to hash table.
              (when current
                (puthash (car current) (mapconcat #'identity (cadr current) " ") table)
                (setq current nil))
              ;; Set current match to be processed on next loop iteration.
              (setq current (list (concat (or (match-string 1 line) (match-string 3 line))  ; If line matches either group 1 or 3 from above, get Prompt number for key
                                          ;; If line matches either group 2 or 4, then convert to number, where a=1, b=2, c=3, and add to subvariant for key.
                                          (if (string= (or (match-string 2 line) (match-string 4 line)) "a")
                                              ".1"
                                            (if (string= (or (match-string 2 line) (match-string 4 line)) "b")
                                                ".2"
                                              ".3")))
                                  ;; If line matched group 5, get Prompt as value and attach to key.
                                  (if (match-string 5 line)
                                      (list (match-string 5 line))
                                    nil))))
             ;; Empty line. Process match from previous loop iteration to hash table.
             ((string-empty-p line)
              (when current
                (puthash (car current) (mapconcat #'identity (cadr current) " ") table)
                (setq current nil)))
             ;; Still not reached end of current Prompt, so add to current for further processing in next loop iteration.
             ((when current
                (setf (cadr current) (append (cadr current) (list line)))))))
          (forward-line 1))
        ;; Catch any outstanding Prompts at end of loop (should hopefully never actually get called).
        (when current
          (puthash (car current) (mapconcat #'identity (cadr current) " ") table)
          (setq current nil))
        ;; If Prompts section was never found, or we didn't find the end of it, report an error to the user.
        (unless found
          (user-error "parse-clean-txt: structural failure, no \"Prompts\" heading found in the txt file (wrong file?)"))
        (if in-section
            (user-error "parse-clean-txt: structural failure, no underline separator found after the Prompts section (corrupt text file?)")
          table))))  ; Return the hash table of Prompts
  (when (boundp 'new-clean-txt)
    (parse-clean-txt new-clean-txt))
#+end_src

To apply my manual edits, I've stored them as a list of operations for each Prompt. Each operation consists of an offset, a number of chars to be deleted, and then any text to insert at the resultant point. Operations are processed on each Prompt from right to left.

#+name: apply-txt-edits
#+begin_src emacs-lisp :tangle no :var new-text="" new-operations=() :results silent
  (defun apply-txt-edits (text operations)
    (dolist (operation (sort operations (lambda (a b) (> (car a) (car b)))))
      (let* ((offset (car operation))
             (del-n (nth 1 operation))
             (insert-txt (nth 2 operation)))
        (unless (and (integerp offset) (>= offset 0) (<= offset (length text))
                     (integerp del-n) (>= del-n 0) (<= (+ offset del-n) (length text)))
          (user-error "apply-txt-edits: operation \"%s\" out of bounds for text of length %d" operation (length text)))
        (setq text (concat (substring text 0 offset)
                           insert-txt
                           (substring text (+ offset del-n))))))
    text)
  (when (and (boundp 'new-text) (boundp 'new-operations))
    (apply-txt-edits new-text new-operations))
#+end_src

When re-run, this code block will update the results section underneath with the next Prompt to resolve. Keep repeating this step to resolve more Prompts until the game ends.

#+name: get-next-prompt
#+begin_src emacs-lisp :tangle no :noweb yes :noweb-prefix no :var lowest-prompt=get-lowest-prompt() highest-prompt=get-highest-prompt() curr-prompt=get-current-prompt() all-prompts=get-all-prompts() used-prompts=get-used-prompts() move-by=move-amount()
  (let ((new-prompt (max lowest-prompt (/ (round (* 10 (+ (+ 0.1 (ffloor curr-prompt)) move-by))) 10.0))))  ; Add the move to the current Prompt, then snap to the nearest tenth (round the x10 value) so float drift can't produce a value that fails to match a stored Prompt
    <<set-current-prompt>>
    <<set-used-prompts>>
    (catch 'prompt-found
      (while (or (not (member new-prompt all-prompts)) (member new-prompt used-prompts))
        (when (> new-prompt highest-prompt)
          (setq new-prompt highest-prompt)
          (throw 'prompt-found t))
        (setq new-prompt (/ (+ 1 (ffloor (* 10 new-prompt))) 10))))  ; Step forward to the next tenth (snapping to whole tenths via ffloor so float drift can't accumulate) until we hit an available Prompt (this does limit the code to working with no more than 9 variants per Prompt)
    (set-current-prompt new-prompt)
    (set-used-prompts (sort (add-to-list 'used-prompts new-prompt) '<))
    (message "%s" (number-to-string new-prompt)))
#+end_src
* Private Gameplay Functions                                       :PRIVATE:
This section exists to store the private functions that fetch not only the next Prompt number, but the next Prompt itself for an entire standard game of /Thousand Year Old Vampire/ using this file alone, and nothing else. This requires the section, [[*Private Variables][Private Variables]] and [[*Private Worker Functions][Private Worker Functions]].

In order to use =get-next-text-prompt= to play the game, you must first (and only once) run =pull-prompts-from-file= below. This will require you to own a copy of version 1.2 of the digital version of /[[https://timhutchings.itch.io/tyov][Thousand Year Old Vampire]]/ by [[https://thousandyearoldvampire.com/][Tim Hutchings]], with the =_Thousand Year Old Vampire.txt= file in the same directory as this Org file.

If everything is working as expected and used correctly, =get-next-text-prompt= is the only function that should ever need to be called to play the game in all future sessions. It simply shows the number and text of the next Prompt that needs to be resolved. The other [[*Gameplay Functions][Gameplay Functions]] can still be used as well.

#+name: pull-prompts-from-file
#+begin_src emacs-lisp :tangle no :noweb yes :noweb-prefix no :var txt-path=get-txt-path() txt-edits=txt-edits() all-prompts=get-all-prompts() :results silent
  <<parse-clean-txt>>
  <<apply-txt-edits>>
  <<set-prompts-text-hash>>
  (let* ((raw-txt (when (file-exists-p txt-path)
                    (with-temp-buffer
                      (insert-file-contents txt-path)
                      (buffer-string))))
         ;; Defensively normalise the text: strip a leading Byte Order Mark [BOM---U+FEFF (ZERO WIDTH NO-BREAK SPACE)/65279] and convert any Windows-style line endings (CRLF) to Unix-style (LF). Files with mixed line endings, in particular, can leave stray \r characters behind that would break parsing.
         (clean-txt (when raw-txt
                      (let* ((byte-order-mark (char-to-string 65279))
                             (no-bom-string (if (string-prefix-p byte-order-mark raw-txt)
                                                (substring raw-txt (length byte-order-mark))
                                              raw-txt)))
                        (replace-regexp-in-string "\r\n" "\n" no-bom-string t))))
         ;; Get hash table of Prompts from clean-txt.
         (parsed-txt (when clean-txt (parse-clean-txt clean-txt))))
    ;; If raw-txt is nil, then the original file was never found, and none of the other processing will have taken place, so inform the user.
    (unless raw-txt
      (user-error "Book file not found: %s. Set #+TXT_PATH to your own copy of the book's original text file (usually called \"_Thousand Year Old Vampire.txt\")." txt-path))
    ;; Check if the Prompts match those expected in terms of amount and numbering. If not, inform the user.
    (let ((found-prompts ()))
      (maphash (lambda (key value)
                 (push (string-to-number key) found-prompts))
               parsed-txt)
      (unless (equal (sort found-prompts) (sort all-prompts))
        (user-error  "Unexpected Prompt amount/numbering found. This is not the expected book text file: %s (the correct text file is usually called \"_Thousand Year Old Vampire.txt\")." txt-path)))
    (let (key
          (prompts-text-hash "(prompts-text-hash\n   #s(hash-table\n      size 300 test eql data\n      (")
          raw-prompt-text
          corrected-prompt-text
          (txt-edits txt-edits)
          <<raw-prompt-text-hashes>>
          <<prompt-text-hashes>>)
      (maphash (lambda (key value)
                 (setq raw-prompt-text (gethash key parsed-txt))
                 ;; If raw-prompt-text matches expected hash, apply corrections. Otherwise, pass straight through.
                 (if (string= (secure-hash 'sha256 raw-prompt-text nil nil nil) (gethash (string-to-number key) raw-prompt-text-hashes))
                     (progn
                       (setq corrected-prompt-text (apply-txt-edits (gethash key parsed-txt) (cdr (assoc (string-to-number key) txt-edits))))
                       (setq prompts-text-hash (concat prompts-text-hash key " \"" corrected-prompt-text "\"\n           "))
                       ;; Check correct text against hash. If wrong, message user but keep going.
                       (unless (string= (secure-hash 'sha256 corrected-prompt-text nil nil nil) (gethash (string-to-number key) prompt-text-hashes))
                         (message "Prompt %s does not contain the expected text" key)))
                   (progn
                     (message "Prompt %s raw text does not match the expected hash; corrections skipped" key)
                     (setq prompts-text-hash (concat prompts-text-hash key " \"" raw-prompt-text "\"\n           ")))))
               parsed-txt)
      (setq prompts-text-hash (concat (string-trim-right prompts-text-hash) ")))"))
      (set-prompts-text-hash prompts-text-hash)
      ;; Now that Prompts have been pulled into the file, display privacy comment on first blank line of file.
      (when prompts-text-hash
        <<add-private-file-comment>>)))
#+end_src
